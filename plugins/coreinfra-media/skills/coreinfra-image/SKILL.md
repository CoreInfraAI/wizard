---
name: coreinfra-image
description: Use when the user asks to generate or edit an image through CoreInfra or Hub, asks for Hub image models or prices, names a Hub image model (Seedream, Nano Banana, FLUX.3 Image, Qwen Image, Recraft, Krea), or asks for an image when this client has no image tool of its own. Not for ordinary image requests while another tool already generates images through the user's plan. It generates and edits image files through CoreInfra Wizard.
---

Use the `coreinfra_media` MCP connector configured by CoreInfra Wizard. Wizard supplies the active generation key for the selected CoreInfra Hub; if the connector is unavailable, ask the user to open Wizard and check that `coreinfra-media` is enabled for this agent.

- **When to use it.** Decide by the tools this client exposes. If another tool already generates images through the user's plan, use it for ordinary image requests and call `image_create` only for an image the user asks from CoreInfra, Hub or a named Hub model, or after the user agrees to spend Hub balance because that tool failed or refused. If there is no image tool, use `image_create` for a request to generate or edit. If a skill names an image tool that is not in your current tool list and this client supports tool search or deferred tools, search for that tool first; only if it is still unavailable, ignore that skill and use `image_create` unless the user asks for that other path.
- Call `image_models` to list current model IDs and prices in RUB per image. A catalog or price request only needs this read. If the user names no model, choose one from the list that suits the request, consider its price, and tell the user which model and price range you chose.
- For a requested image, call `image_create` once with `model` and `prompt`. Pass model options such as `aspect_ratio`, `size`, `quality` or `output_format` as `fields`, or encode that object in `fields_json` if the client needs a fixed schema. `n` (1 to 4) gives variants of one prompt, and each one is billed. For different pictures, make separate calls.
- For edits, put the pictures in the media folder, the `output_dir` that `image_models` returns (by default **Downloads/CoreInfra Media**), and pass their paths in `reference_paths`, absolute or relative to that folder. Wizard reads only that folder. Small pictures can also go inline in `references` as data URIs. References must be PNG, JPEG, WebP or GIF and take at most about 24 MiB together.
- The call is paid and not idempotent. If its outcome is uncertain, explain it to the user before attempting another paid request. If a call was interrupted, the image may still arrive in the media folder. Ask the user to look there before requesting it again.
- Give the user the returned paths in **Downloads/CoreInfra Media** on their computer, with each `content_type` and `size_bytes`. Open the file yourself to check the result. To refine, pass the path of a saved PNG, JPEG, WebP or GIF in `reference_paths`. The location cannot be chosen.

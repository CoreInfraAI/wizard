---
name: coreinfra-image
description: Use when the user asks to generate or edit an image through CoreInfra or Hub, asks for CoreInfra or Hub image models or prices, names a Hub image model (Seedream, Nano Banana, FLUX.3 Image, Qwen Image, Recraft, Krea), or asks for an image and this client has no image tool of its own. Not for ordinary image requests while the client already generates images through the user's plan. It generates and edits images through CoreInfra Hub and saves them locally.
---

Use the tools on the `coreinfra_media` MCP server. Wizard uses the active CoreInfra key of the agent making the request. If the MCP server is unavailable, ask the user to open Wizard and check that `coreinfra-media` is enabled for this agent.

- **When to use it.** Decide by the tools this client exposes. If it already generates images through the user's plan, use that tool for ordinary image requests and call `image_create` only for an image the user asks from CoreInfra, Hub or a named Hub model, or after the user agrees to spend Hub balance because that tool failed or refused. If it has no image tool, use `image_create` for a request to generate or edit. If a skill names an image tool that is not in your current tool list and this client supports tool search or deferred tools, search for that tool first; only if it is still unavailable, ignore that skill and use `image_create` unless the user asks for that other path.
- Call `image_models` for current model IDs and public RUB-per-image rates. A request for models or prices only calls for this read. If the user names no model, choose one from the list that suits the request, consider its price, and tell the user which model and price range you chose. Its `output_dir` is the media folder where images are saved.
- To generate or edit, call `image_create` once with `model` and `prompt`. Put model options such as `aspect_ratio`, `size`, `quality` or `output_format` in `fields`, or in `fields_json` for a client with fixed object schemas. `n` (1 to 4) gives variants of one prompt, and each one is billed. For different pictures, make separate calls.
- References: put the pictures in the media folder **Downloads/CoreInfra Media** and pass their paths in `reference_paths`, absolute or relative to that folder. Wizard reads only that folder. Small pictures can also go inline in `references` as `data:image/...;base64,...`. References must be PNG, JPEG, WebP or GIF and take at most about 24 MiB together.
- The call is paid and not idempotent. If the outcome is uncertain, report it instead of retrying. A second call can incur another charge. If a call was interrupted, the image may still arrive in the media folder. Tell the user to look there before asking for it again.
- Wizard saves each image as **Downloads/CoreInfra Media/image-<random>.<ext>** and returns `{images: [{path, content_type, size_bytes}], usage}`. Open the file with your own viewer to check the result, then give the user its absolute `path`. To refine, pass the path of a saved PNG, JPEG, WebP or GIF in `reference_paths`. The output location cannot be chosen.
